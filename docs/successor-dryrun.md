# 후임자 예행연습 체크리스트 (새 컴퓨터에서 처음부터 설치해 실행하기)

이 문서는 **후임 임원진이 새 컴퓨터에서 처음부터 설치하고 실행해 보는 연습표**입니다. 설명은 일부러 짧게 했고, 자세한 방법은 `HANDOVER.md`의 해당 절을 가리킵니다(절 번호는 그 문서 기준). 이 문서와 `HANDOVER.md`가 다르면 **`HANDOVER.md`가 맞습니다.**

- 소요 시간: 처음 하는 사람 기준 1~2시간(설치가 오래 걸리면 더).
- **연습은 시험용 Supabase 프로젝트로 하는 것이 안전합니다.** 내 컴퓨터에서 띄운 화면도 `.env`에 적은 Supabase에 연결되므로, 운영 값을 넣으면 연습 데이터가 실제 데이터에 들어갑니다(`HANDOVER.md` 4번 첫 문단).
- 비밀번호·키·개인정보는 이 문서나 채팅·메신저에 적지 않습니다. 기록은 "됨/안 됨"과 막힌 단계 번호만 남깁니다.
- 각 단계는 **끝나면 체크**하고, 막히면 맨 아래 "막혔을 때"로 갑니다.

## 0. 시작 전에 (사람이 정할 것)
- [ ] 연습에 쓸 **시험용 Supabase 프로젝트**가 있다(없으면 만들어 달라고 임원진에게 요청). 운영 프로젝트에 연결하지 않는다.
- [ ] 키를 받는 방법이 정해져 있다: 비밀번호 관리 도구로만 전달받고 채팅·메신저·이메일로 받지 않는다(`HANDOVER.md` 3-0).
- [ ] 필요한 계정이 있다: GitHub(저장소 접근 권한 포함), Supabase, Vercel(`HANDOVER.md` 3-0, 3장 전체).

## 1. 컴퓨터 준비 (`HANDOVER.md` 4-1)
- [ ] **Git**을 설치했다. 확인: `git --version`
- [ ] **Node.js**(LTS)를 설치했다. 버전이 **20.19 이상 또는 22.12 이상**이다. 확인: `node --version`
- [ ] `npm`이 된다. 확인: `npm --version`
- [ ] (선택) VS Code를 설치했다.
- [ ] 터미널(Windows는 PowerShell)을 열 수 있다.

## 2. 내려받기와 설치 (`HANDOVER.md` 4-2)
- [ ] 저장소를 내려받았다(`git clone` 주소는 4-2에 있다. 저장소를 이전했다면 새 주소를 쓴다).
- [ ] 프로젝트 폴더로 이동했다. 확인: 폴더 안에 `package.json`, `HANDOVER.md`가 보인다.
- [ ] `npm install`이 오류 없이 끝났다(경고는 괜찮다).
- [ ] `git status`가 깨끗하다(바뀐 파일 없음).

## 3. 환경변수 (`HANDOVER.md` 4-3)
- [ ] `.env.example`을 복사해 `.env`(또는 `.env.local`)를 만들었다.
- [ ] 값 3개를 **시험용 프로젝트** 것으로 채웠다: Project URL, 화면용 공개 키, `VITE_ID_EMAIL_DOMAIN`.
- [ ] Supabase **서비스 롤(Secret) 키는 `.env`에 넣지 않았다**(서버 함수 전용, Vercel 환경변수에만 둔다).
- [ ] `git status`에 `.env`가 나타나지 않는다(`.gitignore`가 막고 있다). 나타나면 **커밋하지 말고** 멈춘다.

## 4. 데이터베이스 준비 (시험용 프로젝트가 비어 있을 때만, `HANDOVER.md` 8-1)
- [ ] 8-1 표의 **1~37번**을 순서대로 SQL Editor에서 실행했다(맨 위 설명에 "구간을 나눠서 실행"이라고 적힌 파일은 구간별로).
- [ ] `remove_signup_code.sql`(34번)을 가입 함수 파일 중 **마지막에** 실행했다(35번 `add_library_archive_ext.sql`, 36번 `add_library_size_50mb.sql`, 37번 `add_library_zip_mime.sql`은 그 다음에 실행해도 된다).
- [ ] 앱에서 연습용 계정 2개로 가입하고, 8-1의 "첫 임원진 지정" 문장으로 임원진을 만들었다.
- [ ] (이미 SQL이 적용된 시험용 프로젝트라면 이 단계는 건너뛴다.)

## 5. 실행해 보기 (`HANDOVER.md` 4-4)
- [ ] `npm run dev`를 실행했고 `http://localhost:5173`이 열렸다.
- [ ] 로그인 화면이 보인다.
- [ ] 임원진 계정으로 로그인했고 **허브**("무엇을 할까요?" 카드 4개)가 보인다.
- [ ] 상단의 **관리** 메뉴가 보이고 열린다(임원진만).
- [ ] 부원 계정(또는 승인 후 새 가입 계정)으로 로그인해 **관리** 메뉴가 **보이지 않는다**.
- [ ] 종료는 터미널에서 `Ctrl+C`.

## 6. 빌드와 검사 (`HANDOVER.md` 4-4)
- [ ] `npm run build`가 끝났다(번들 크기 경고는 정상이다).
- [ ] `npm run lint`가 끝났다.
- [ ] 실패하면 오류 문구를 복사해 둔다(키·개인정보가 섞이지 않았는지 보고 나서 공유한다).

## 7. 화면 점검 (계정 3종 × 폭 5개)
브라우저에서 `F12` → 기기 모양 아이콘으로 폭을 바꿔 봅니다.
- [ ] 계정: 임원진 / 부원 / 졸업생(임원진이 관리 화면에서 **졸업 지정**해 만든다, `HANDOVER.md` 5-2)
- [ ] 폭: 320 / 360 / 390 / 768 / 1000px 이상
- [ ] 허브, 달력, 토론, 활동 기록, 포트폴리오 화면이 깨지지 않는다.
- [ ] 졸업생에게는 "내 시간표", "공통 시간", 콘텐츠 플래너 메뉴가 **보이지 않는다**.

## 8. 서버 함수(활동 찾기)는 내 컴퓨터에서 안 된다 (`HANDOVER.md` 4-4, 7-2)
- [ ] `npm run dev`로는 `api/` 폴더(활동 찾기)가 실행되지 않는다는 것을 이해했다.
- [ ] 활동 찾기는 **배포(미리보기)** 주소에서 확인한다(9번 연습 후).

## 9. 배포 흐름 연습 (`HANDOVER.md` 9-1) — 병합하지 않는다
- [ ] 새 브랜치를 만들었다(예: `practice/dryrun`). **`main`에서 직접 작업하지 않는다.**
- [ ] 아주 작은 변경(예: 문서의 띄어쓰기 한 곳)을 하고 `npm run build`, `npm run lint`를 통과시켰다.
- [ ] 변경한 파일만 `git add`해서 커밋했다. 비밀 값 파일이 들어가지 않았는지 `git status`로 확인했다.
- [ ] 브랜치를 올리고 **PR**(수정 제안)을 만들었다.
- [ ] Vercel이 만든 **미리보기 주소**가 열린다. 그 주소에서 로그인과 활동 찾기를 확인했다.
- [ ] **PR을 병합하지 않고 닫았다**(연습이기 때문). 연습 브랜치를 지웠다.
- [ ] (환경변수·롤백은 Vercel Owner 계정에서만 가능한지 확인했다: `HANDOVER.md` 3-3)

## 10. AI 도구로 이어서 개발하는 연습 (선택, `HANDOVER.md` 11번)
- [ ] Claude Code(또는 다른 AI 도구)를 설치했다(`HANDOVER.md` 11-1, 11-6).
- [ ] 첫 대화로 이렇게 요청해 봤다: "`CLAUDE.md`와 `HANDOVER.md`를 읽고 구조를 쉬운 말로 설명해 줘. 아직 아무것도 고치지 마."
- [ ] 비밀 값(키, 비밀번호)을 대화에 붙여 넣지 않았다.

## 11. 끝났을 때 확인 (완료 기준)
- [ ] 위 1~7번을 모두 체크했고 막힌 단계가 없다(또는 막힌 단계를 기록해 `HANDOVER.md` 고칠 곳으로 알렸다).
- [ ] 이 연습으로 `main`에 올라간 것이 **없다**(`git log origin/main`이 연습 전과 같다).
- [ ] 시험용 계정·데이터를 정리했다(필요하면 `supabase/handover_cleanup_DRAFT.sql` 참고, 실행은 관리자만).

## 막혔을 때
| 증상 | 먼저 볼 곳 |
|---|---|
| `npm install`이 실패한다 | Node 버전 확인(1번). 오류 마지막 줄을 기록 |
| 화면이 안 뜨거나 "불러오지 못했습니다" | `.env` 값이 비었거나 틀림(3번). Supabase가 일시정지됐는지(`HANDOVER.md` 6-2) |
| 로그인이 안 된다 | `VITE_ID_EMAIL_DOMAIN`이 가입 때 쓴 값과 같은지, 계정이 **승인**됐는지(`HANDOVER.md` 5-1, 7-1) |
| 특정 화면만 오류가 난다 | 그 기능의 SQL이 시험용 프로젝트에 실행됐는지(4번, `HANDOVER.md` 8-1) |
| `git push`가 거부된다 | `main`에 직접 올리려는 것은 아닌지(9번). 브랜치로 올린다 |
| 활동 찾기가 안 된다 | 내 컴퓨터에서는 정상적으로 안 된다(8번). 미리보기에서 확인(`HANDOVER.md` 7-2) |

그 밖의 증상은 `HANDOVER.md` 7-1의 표를 봅니다. 이 연습표에서 어색했던 곳은 `HANDOVER.md`를 고칠 때 반영하도록 임원진에게 알려 주세요.
